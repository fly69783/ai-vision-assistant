# 测试说明

## 测试分两层

1. **自动化测试**：使用程序生成的图片，检查配置、质量门、融合、播报、错误处理和API。
2. **功能评测**：使用有合法来源的固定场景图片，检查真实模型准确性和端到端成功率。

自动化测试通过，只能说明代码骨架正常，不能说明AI识别准确。

当前工程基线是66项自动化测试全部通过，`app`与`core`覆盖率89%。测试覆盖配置、图片质量、融合、编排、上传边界、API响应策略、PWA静态资源、检测/OCR/本地视觉/云端视觉适配器的离线模拟响应和固定评测清单工具。这组数字不代表目标检测、OCR或视觉理解准确率；模型效果仍必须使用固定场景单独评测。

## 固定测试集

- 10个室内环境概述场景。
- 10个文字读取场景。
- 10个物品查找场景。
- 10个困难场景：低光、模糊、遮挡、多人或杂乱背景。

调试图片和最终测试图片必须分开，避免只对已经见过的图片优化。

## 每条用例记录什么

使用`test-cases.csv`记录：编号、场景、任务、输入来源、授权和预期。真实结果由`run_fixed_evaluation.py`写入被Git忽略的`output/`目录，避免把本地图片路径和临时结果混入版本库。

完整采集、检查和运行步骤见[训练前固定场景评测指南](./fixed-scene-guide.md)。清单检查命令：

```powershell
python scripts\run_fixed_evaluation.py --check-only
```

服务启动后运行真实基线：

```powershell
python scripts\run_fixed_evaluation.py
```

失败类型建议统一为：

- `input_quality`：画面本身不适合分析。
- `false_positive`：识别出不存在的内容。
- `false_negative`：漏掉应识别内容。
- `ocr_error`：文字错误或顺序错误。
- `hallucination`：视觉模型生成无依据内容。
- `timeout`：超过设定时间。
- `interaction`：操作或播报难以理解。

## 运行自动化测试

```powershell
python -m pytest --cov=app --cov=core --cov-report=term-missing
```

提交前运行完整质量脚本：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_tests.ps1
```

## 浏览器验收矩阵

| 场景 | 验收重点 |
|---|---|
| 桌面在线 | 选择/拖放图片、预览、分析、结果聚焦、语音按钮、控制台无异常 |
| 390×844手机 | 无横向滚动、拍照/相册入口、44px触摸目标、长文字自然换行 |
| 纯键盘 | 首次Tab出现跳转链接、表单可操作、完成后焦点到结果标题 |
| 非图片/损坏/超限文件 | 给出可理解错误，不发送或不继续分析 |
| 离线刷新 | 静态外壳可打开，API不从缓存返回，显示服务不可达 |
| 网络恢复 | 健康状态自动恢复，离线横幅消失 |
| PWA更新 | 等待Worker出现更新按钮，点击后接管、刷新并加载新版本 |

浏览器验收时还要检查Cache Storage不包含`/api/`、上传图片或分析结果。
